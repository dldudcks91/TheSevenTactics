# TheSevenTactics 개발 계획서

> 내러티브 전술 RPG로 방향 전환. 사기 시스템 중심 재설계.

---

## 기술 스택

| 구분 | 기술 |
|------|------|
| 서버 | FastAPI (async) + uvicorn |
| DB | MySQL + SQLAlchemy ORM |
| 캐시 | Redis (async, 세션/전투 상태) |
| 클라이언트 | Vanilla JS (ES Modules) + Phaser.js |
| 데이터 | CSV 메타데이터 (서버 시작 시 로드) |
| API | 단일 /api 게이트웨이 (api_code 라우팅) |
| 인증 | Redis 세션 (Bearer 토큰) |

---

## 개발 이력 (Phase 1~6: RPG 시절)

> Phase 1~6은 전통 RPG 구조로 개발된 것. 방향 전환으로 대부분 재설계 필요.

| Phase | 내용 | 상태 |
|-------|------|------|
| 1 | 프로젝트 뼈대 복사 (서버/클라 구조) | ✅ 유지 |
| 2 | DB 모델 (User/Hero/Party/Tavern) | ✅ → 재설계 필요 |
| 3 | 핵심 시스템 (HeroManager/TavernManager/BattleManager) | ✅ → 재설계 필요 |
| 4 | 클라이언트 UI (영웅/파티/장비/전투 탭) | ✅ → 재설계 필요 |
| 5 | 전투씬 구현 (Phaser.js) | ✅ → 사기 효과 추가 필요 |
| 6 | RPG 시스템 이식 (장비/드롭/상태이상/몬스터) | ✅ → 간소화 필요 |

## 방향 전환 후 개발 Phase

### Phase N1: 기획 재설계

**목표**: 내러티브 전술 RPG 기획 확정

```
✅ 게임 방향 전환 결정 (전통 RPG → 내러티브 RPG)
✅ 사기 시스템 기본 설계 (수치/구간/효과)
✅ 바알 죄종 선택 시스템
✅ 죄종 관계 매트릭스
✅ 이벤트 선택지 구조 (서사/원정/암묵적)
✅ GAME_DESIGN.md 전면 재작성
□ 영웅별 사기 스킬 상세 설계 (27체 × 2스킬)
□ 연계 스킬 목록
□ 이벤트 선택지 전체 목록 (챕터별)
□ 사기 수치 밸런싱 (시뮬레이션)
```

### Phase N2: DB 모델 재설계

**목표**: 사기 시스템에 맞는 데이터 모델

```
변경 모델:
□ Hero — morale(사기) 컬럼 추가, skill_tree 관련 컬럼 삭제
□ User — baal_sin(바알 죄종) 컬럼 추가
□ Party — 기존 유지

신규 모델:
□ EventChoice — 플레이어 선택 기록 (챕터/이벤트ID/선택지)
□ MoraleLog — 사기 변동 기록 (영웅/변동량/원인)

삭제 모델:
□ HeroSkillTree — 사기 스킬로 대체
```

### Phase N3: 사기 시스템 서버 구현

**목표**: 사기 변동 + 전투 연동

```
서버 매니저:
□ MoraleManager — 사기 계산/변동/조회
  - 플레이어 행동 → 영웅별 사기 변동
  - 파티 조합 보정 계산
  - 전투 결과 반영
  - 바알 지휘관 보정
□ EventManager — 이벤트 선택지 처리
  - 서사 선택지 (챕터별 고정)
  - 원정 이벤트 (랜덤 풀에서 선택)
  - 선택 결과 → MoraleManager 호출
□ BattleManager 수정
  - 사기 구간별 행동 변경 (불복/추가행동)
  - 사기 스킬 해금 판정
  - 연계 스킬 발동 판정
  - 전투 중 사기 변동 이벤트

CSV 메타데이터:
□ event_choices.csv — 이벤트별 선택지 + 사기 변동 수치
□ morale_skills.csv — 영웅별 사기 스킬 1/2 데이터
□ combo_skills.csv — 연계 스킬 조합 + 효과
```

### Phase N4: 클라이언트 재설계

**목표**: 사기 시스템 UI + 이벤트 선택지 UI

```
신규 화면:
□ 죄종 선택 화면 (게임 시작 시)
□ 이벤트 선택지 UI (웨이브 사이 팝업)
□ 사기 표시 (영웅 상세, 파티 편성)

수정 화면:
□ 파티 편성 — 죄종 궁합 표시 + 예상 사기 보정
□ 전투 뷰 — 사기 상태 표시 + 명령 불복 연출 + 사기 스킬 연출
□ 영웅 상세 — 사기 스킬 해금 상태 표시
□ 선술집 — 초기 사기 미리보기 (바알 죄종 기반)
```

### Phase N5: 이벤트/서사 콘텐츠

**목표**: 7챕터 이벤트 선택지 + 원정 이벤트 풀

```
□ 챕터별 서사 선택지 작성 (7챕터 × 2~3개)
□ 원정 이벤트 풀 작성 (20~30개)
□ 암묵적 행동 추적 구현 (영웅 관리/자원/전투 패턴)
□ 사기 밸런싱 테스트
```

## 핵심 설계 결정사항 (확정)

| 항목 | 결정 |
|------|------|
| 게임 방향 | 내러티브 전술 RPG (파밍 RPG에서 전환) |
| 핵심 시스템 | 사기(Morale) — 영웅별 0~100, 5구간 |
| 바알 죄종 | 게임 시작 시 7택1. 영웅 초기 사기 결정 |
| 사기 변동 | 플레이어 행동 + 파티 조합 + 전투 이벤트 |
| 사기 효과 | 높으면 스킬 해금, 낮으면 명령 불복 |
| 이벤트 | 서사 선택지 + 원정 이벤트 + 암묵적 추적 |
| 전투 | 3인 파티 자동전투, 행동 게이지 기반 |
| 영웅 | 27체 + 바알(지휘관), 각 1개 죄종 |
| 직업 | 5종 (전직 없음) |
| 장비 | 3슬롯 (무기/갑옷/장신구), 죄종 접사 |
| 참고 게임 | DD1/DD2, HoMM3, 삼국지6 |
